# 네 커밋 최종 검토

> 후속 상태: 2026-10-27 사용자 승인 후 포크 Release를 공개하고 기본 의존성 전환을 진행했다. 아래는 전환 전 기록이며 현재 결과는 [XLS 수정·전환 검증](XLS_CHART_FIX.md)을 따른다.

2026-10-27. 대상은 `06fb134` → `2572a4c` → `201ad89` → `1af59ff`다. 기존 엔진 전체를 새로 감사한 결과가 아니라 네 커밋의 변경과 그 검증 경계를 검토했다.

| 커밋 | 검토 내용 | 결과 |
|---|---|---|
| `06fb134` 테스트·자산 | testTarget 범위, 65문서 해시·부분 정답, 생성/외부 샘플 구분, 출처·고지, 위험 입력 검사 | 제품 타깃에 테스트 자산을 연결하지 않음. 실기기 corpus 포함 전체 검사 통과 |
| `2572a4c` 오류 정규화 | 기존 오류 유지, 외부 오류 정보 차단, 취소, 단일/배치 분류와 최종 이벤트 | 실제 손상 BIFF로 같은 malformedDocument·실패 후 다른 결과 보존·임시 파일 정리 통과 |

이번 변경에서 새로 도입된 것으로 확인되는 수정 필수 기능 결함은 찾지 못했다. 수정 구성의 기존 16개 테스트는 iPhone 17 실기기에서 모두 통과했다. SwiftLint strict도 별도로 실행했다. 테스트에 없는 동작까지 정확성·안전성·완전한 복원으로 확대 해석하지 않는다.

## 배포 전에 남는 사항

1. **운영 기본 구성에는 기존 XLS 결함이 남는다.** upstream 7.5.2를 바꾸지 않았으므로 기본 전체 테스트는 기존 15/16 결과다. 수정 구성의 16/16을 운영 기본 결과로 쓰면 안 된다.
2. **원격 배포는 아직 없다.** 공개 소스/Release, 번들 버전, checksum, 전이 고지 대응, 원격 클린 설치와 재검증이 필요하다. [전환 템플릿과 순서](ODR_MIGRATION_PREPARATION.md)를 준비했으며 실제 manifest에는 적용하지 않았다.
3. 실기기 corpus 실행에 QoS 우선순위 역전 경고가 있었다. 호출 위치만으로 원인을 단정하지 않는다. [실기기 결과와 한계](ODR_PHYSICAL_VERIFICATION.md)에 남겼다.
4. 16개 테스트는 중간 OCR/배치 취소, native 압축 해제의 모든 공격 조합, 대용량 최대 메모리까지 입증하지 않는다. 기존 실패를 숨기는 skip이나 출력 기반 정답 갱신은 하지 않았다.

이번 후속 작업의 저장소 변경은 검증 기록과 미적용 전환 템플릿이다. 제품 Swift 코드·기존 테스트·런타임 바이너리·의존성·서명 설정은 바꾸지 않았으며 커밋·푸시·외부 게시는 하지 않았다.
